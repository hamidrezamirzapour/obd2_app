# همراه خودرو — MVP اندروید

پروژهٔ نمونهٔ Kotlin Native برای خواندن محدود داده‌های عمومی OBD-II از دانگل ELM327 بلوتوث کلاسیک. شناسهٔ برنامه `ir.hamidreza.autodiag` است. رابط کاربری فارسی و راست‌چین است؛ اجزای رابط در Kotlin ساخته می‌شوند و فایل XML رابط لازم نیست.

## محدودیت‌ها و نکات ایمنی

- این برنامه فقط چند فرمان عمومی OBD-II مربوط به قوای محرکه را امتحان می‌کند: RPM، سرعت، دمای مایع خنک‌کننده، خواندن کدهای Mode 03 و درخواست پاک‌کردن Mode 04. پوشش و پاسخ به خودرو، ECU، دانگل و firmware وابسته است؛ سازگاری با همه خودروها، از جمله خودروهای ایرانی، تضمین نمی‌شود.
- این ابزار ABS، ایربگ، BSI، ایموبلایزر یا همه ECUها را اسکن نمی‌کند و جایگزین عیب‌یابی تعمیرگاهی نیست. شرح کدها صرفاً عمومی است؛ علت‌یابی و تعمیر را به متخصص بسپارید.
- پاک‌کردن کد علت خرابی را رفع نمی‌کند و ممکن است کدها و داده‌های آمادگی آلایندگی را پاک کند. فقط پس از بررسی و با آگاهی اقدام کنید.
- فقط Bluetooth Classic/SPP استفاده می‌شود؛ BLE پشتیبانی نمی‌شود. پاسخ ناقص/ناموفق به‌عنوان «بدون خطا» اعلام نمی‌شود. برخی دانگل‌ها با وجود نام ELM327 ناسازگار یا دارای firmware متفاوت‌اند.
- برنامه دستگاه جدیدی را جست‌وجو نمی‌کند؛ فهرست فقط دستگاه‌های از قبل جفت‌شده را نشان می‌دهد. در صورت خاموش‌بودن بلوتوث، برنامه پیام راهنما می‌دهد و آن را خودکار روشن نمی‌کند.

## استفاده و جفت‌سازی

1. خودرو را در محل امن پارک کنید. سوئیچ را روشن کنید (برای برخی خودروها موتور روشن لازم است).
2. دانگل را وصل کنید و از تنظیمات Android آن را با گوشی جفت کنید؛ PIN، اگر درخواست شد، مطابق راهنمای دانگل است.
3. برنامه را باز کنید، مجوز اتصال بلوتوث را در Android 12 به بعد بدهید و دستگاه جفت‌شده را انتخاب کنید.
4. اتصال را بزنید. برنامه فرمان‌های پایه ELM را می‌فرستد و سپس PIDهای پشتیبانی‌شده را دوره‌ای می‌خواند. برای بررسی/پاک‌کردن کدها از دکمه مربوط استفاده کنید.
5. یادآور سرویس (نام خودرو و کیلومترها) فقط در SharedPreferences همین گوشی ذخیره می‌شود و به خودرو متصل یا با فضای ابری همگام نیست.

## ساخت APK در GitHub Actions

1. محتوای این پروژه را در یک مخزن جدید GitHub بارگذاری کنید (از دکمه **Add file → Upload files** یا `git init`، سپس commit و push استفاده کنید).
2. workflow در `.github/workflows/build-apk.yml` با push، pull request یا اجرای دستی فعال می‌شود؛ JDK 17، Android SDK 35، Build Tools 35.0.0 و Gradle 8.9 را آماده و `assembleDebug` را اجرا می‌کند.
3. در مخزن وارد زبانه **Actions** شوید، اجرای موفق را باز کنید و از بخش **Artifacts** فایل `app-debug` را دانلود کنید. APK داخل artifact با مسیر `app/build/outputs/apk/debug/app-debug.apk` ساخته می‌شود.

## ساخت محلی در Android Studio

- نسخهٔ Android Studio با پشتیبانی از AGP 8.7.3 و JDK 17 نصب کنید.
- پروژه را باز کنید و اجازه دهید Android SDK Platform 35 و Build Tools 35.0.0 نصب شوند. Gradle 8.9 موردنیاز است (wrapper در این پروژه عمداً قرار ندارد؛ می‌توانید Gradle 8.9 را نصب کنید و `gradle --no-daemon assembleDebug` اجرا کنید).
- خروجی debug در `app/build/outputs/apk/debug/app-debug.apk` قرار می‌گیرد. این خروجی برای انتشار نهایی/signing production نیست.

## مجوزها و ملاحظات

در Android 12 و جدیدتر، مجوز زمان اجرا `BLUETOOTH_CONNECT` برای خواندن دستگاه‌های جفت‌شده و اتصال لازم است. در Android 11 و پایین‌تر مجوزهای legacy بلوتوث در Manifest تا API 30 تعریف شده‌اند. برنامه اسکن discovery انجام نمی‌دهد، بنابراین مجوز location یا `BLUETOOTH_SCAN` درخواست نمی‌کند. اتصال RFCOMM ممکن است با دانگل خاموش، مشغول، خارج از محدوده یا غیرقابل‌اعتماد ناموفق شود؛ ابتدا اتصال‌های دیگر دانگل را قطع و سپس دوباره تلاش کنید.
